Project 1 — Accentra: AI-Powered Language Learning Platform
Repository: https://github.com/Kshitij-Vijay-Pawar/accentra
Type: Full-stack language-learning web application
Portfolio priority: Featured project
Overview
Accentra is a language-learning application with a course-and-lesson experience. Its implementation includes structured courses, units, lessons, interactive challenges, user progress, hearts, points, quests, a leaderboard, a shop, an AI-assisted grammar conversation endpoint, and subscription-related code.

The product experience is inspired by gamified language-learning platforms. Describe it as a language-learning platform; do not claim it is a clone of a particular product unless Kshitij explicitly wants that comparison.
Implemented functionality visible in the repository
- Course, unit, lesson, challenge, and challenge-option data models.
- A learning area that loads the user's active course and ordered learning units.
- Interactive lesson/quiz flow with challenge progress.
- Progress calculations for lessons and courses.
- Gamification-related user state, including hearts and points.
- Course selection and course progress handling.
- Leaderboard, quests, shop, and learning navigation UI.
- Admin interfaces and API routes for managing courses, units, lessons, challenges, and challenge options.
- Clerk-based authentication integration.
- AI chatbot API route using Google's Generative AI SDK and the Gemini gemini-2.0-flash model. The prompt asks the model to identify grammar errors, provide a correction and explanation, and continue the conversation as a friendly English teacher.
- Stripe integration code and a Stripe webhook route for subscription-related functionality.
Technical architecture
- Application framework: Next.js 15.2.3 with App Router.
- UI: React 18, Tailwind CSS 4, Radix UI components, Lucide icons.
- Language: TypeScript.
- Authentication: Clerk (@clerk/nextjs).
- Database: PostgreSQL through Neon serverless driver.
- ORM: Drizzle ORM and Drizzle Kit.
- AI integration: @google/generative-ai; Gemini model configured in the chatbot route.
- Payments/subscriptions: Stripe SDK.
- Client state: Zustand.
- Other UI utilities: React Admin, React Confetti, React Circular Progressbar, Sonner, React Use.
Data model and engineering details
The Drizzle schema includes relational tables for:
- courses
- units
- lessons
- challenges
- challenge_options
- challenge_progress
- user_progress
- user_subscription
The schema defines relations between courses, units, lessons, challenges, and challenge options. User progress tracks the active course, hearts, and points. Challenge progress is associated with a user and challenge.

The query layer uses Clerk's server-side auth() to identify the current user, Drizzle relational queries to load learning content, and React's cache() to memoize data access during server rendering. It calculates completed lessons and course progress from challenge completion records.
Good engineering story to explain
A strong case study can explain how the learning path is represented as relational data:
1. A course contains ordered units.
2. Each unit contains ordered lessons.
3. Lessons contain ordered challenges.
4. Challenge options represent answer choices and correctness.
5. User challenge-progress records drive completion state.
6. Server-side queries assemble the nested learning path and calculate progress for the UI.
Another useful story is the AI tutor endpoint: a user submits a sentence, the server calls Gemini with a structured teaching prompt, and the route returns the generated correction/explanation/reply.

Implemented relational learning-content models with Drizzle ORM and PostgreSQL, authenticated user workflows with Clerk, and integrated Gemini for conversational grammar feedback."

Project 2 — Google Maps Lead Scraper and Enrichment API
Backend repository: https://github.com/Kshitij-Vijay-Pawar/scraper
Frontend repository: https://github.com/Kshitij-Vijay-Pawar/scraper-ui
Type: Full-stack lead-generation and web-scraping application
Portfolio priority: Featured project
Overview
This project is a lead-generation system that accepts a business keyword and location, runs Google Maps scraping as an asynchronous background job, stores business records, removes duplicates, enriches records from business websites, and exports lead data.

The backend and UI are separate repositories. Present them as the backend and frontend of the same product only if Kshitij confirms they were developed and deployed together as one application.
Backend: verified implementation
Google Maps scraping
- Uses Playwright Chromium in headless mode to navigate Google Maps.
- Searches using a combination of business keyword and location.
- Detects and attempts to handle a Google consent screen.
- Waits for business-place links and scrolls the results feed to load more results.
- Stops scrolling when the requested limit is reached, the feed ends, or repeated scroll attempts stop changing the feed.
- Opens individual business result pages and extracts available details.
- The scraper code includes extraction for business name, rating, review count, address, phone, website, and geographic coordinates. Additional fields should only be listed if confirmed in the complete extraction and persistence flow.
Asynchronous job processing
- Express 5 API exposes search endpoints.
- Search requests are validated with Zod.
- The API creates a search record in PostgreSQL and queues a BullMQ job.
- The API returns a search ID and job ID without waiting for the scrape to finish.
- A separate BullMQ worker processes the search job.
- The worker updates search status and progress as it moves through scraping and persistence/deduplication steps.
- Redis is used as the BullMQ connection.
- The API includes graceful shutdown handling for the HTTP server, queues, and Redis connection.
Lead deduplication
The deduplication service checks records using a priority strategy:
1. Website.
2. Phone number.
3. Email address.
4. Normalized business name plus address when website, phone, and email are unavailable.
It also uses in-memory sets to detect duplicates within the current batch and batch database queries to compare incoming records against existing records. This is a strong technical detail to highlight because it shows more than simply scraping and inserting rows.
Website enrichment
- Uses Axios to fetch business websites.
- Uses Cheerio to parse HTML.
- Extracts email addresses from mailto: links and page text.
- Discovers and visits a limited number of same-domain contact/about/team/support pages.
- Extracts social profile links for Facebook, Instagram, LinkedIn, and X/Twitter.
- Selects a preferred email using a priority list such as sales, contact, info, support, and admin.
- Preserves the original Google Maps data as the primary source of truth: enrichment is designed to fill missing fields rather than overwrite existing non-null values.
Enrichment jobs
- Enrichment requests are queued separately through BullMQ.
- The API checks that selected leads belong to searches owned by the requesting user.
- The API limits an enrichment job to 500 leads.
- The worker processes leads in batches of five with worker concurrency configured to five.
- It tracks completed and failed leads, updates job progress, skips already-enriched leads unless forced, and checks for cancellation between batches.
- The API exposes enrichment progress and cancellation routes.
Export
- Exports lead records to CSV and Excel (.xlsx).
- Export data includes fields such as name, phone, email, website, address, rating, review count, social links, latitude, and longitude.
- Export routes check search ownership before returning files.
API access and security-related code
The repository includes:
- User authentication middleware.
- API-key authentication middleware and a combined auth-or-API-key middleware.
- API-key routes.
- Audit-log middleware.
- Search ownership checks for user-specific data and exports.
- Zod request validation.

Type: Full-stack language-learning web application
Portfolio priority: Featured project
Overview
Accentra is a language-learning application with a course-and-lesson experience. Its implementation includes structured courses, units, lessons, interactive challenges, user progress, hearts, points, quests, a leaderboard, a shop, an AI-assisted grammar conversation endpoint, and subscription-related code.

The product experience is inspired by gamified language-learning platforms. Describe it as a language-learning platform; do not claim it is a clone of a particular product unless Kshitij explicitly wants that comparison.
Implemented functionality visible in the repository
- Course, unit, lesson, challenge, and challenge-option data models.
- A learning area that loads the user's active course and ordered learning units.
- Interactive lesson/quiz flow with challenge progress.
- Progress calculations for lessons and courses.
- Gamification-related user state, including hearts and points.
- Course selection and course progress handling.
- Leaderboard, quests, shop, and learning navigation UI.
- Admin interfaces and API routes for managing courses, units, lessons, challenges, and challenge options.
- Clerk-based authentication integration.
- AI chatbot API route using Google's Generative AI SDK and the Gemini gemini-2.0-flash model. The prompt asks the model to identify grammar errors, provide a correction and explanation, and continue the conversation as a friendly English teacher.
- Stripe integration code and a Stripe webhook route for subscription-related functionality.
Technical architecture
- Application framework: Next.js 15.2.3 with App Router.
- UI: React 18, Tailwind CSS 4, Radix UI components, Lucide icons.
- Language: TypeScript.
- Authentication: Clerk (@clerk/nextjs).
- Database: PostgreSQL through Neon serverless driver.
- ORM: Drizzle ORM and Drizzle Kit.
- AI integration: @google/generative-ai; Gemini model configured in the chatbot route.
- Payments/subscriptions: Stripe SDK.
- Client state: Zustand.
- Other UI utilities: React Admin, React Confetti, React Circular Progressbar, Sonner, React Use.
Data model and engineering details
The Drizzle schema includes relational tables for:
- courses
- units
- lessons
- challenges
- challenge_options
- challenge_progress
- user_progress
- user_subscription
The schema defines relations between courses, units, lessons, challenges, and challenge options. User progress tracks the active course, hearts, and points. Challenge progress is associated with a user and challenge.

The query layer uses Clerk's server-side auth() to identify the current user, Drizzle relational queries to load learning content, and React's cache() to memoize data access during server rendering. It calculates completed lessons and course progress from challenge completion records.
Good engineering story to explain
A strong case study can explain how the learning path is represented as relational data:
1. A course contains ordered units.
2. Each unit contains ordered lessons.
3. Lessons contain ordered challenges.
4. Challenge options represent answer choices and correctness.
5. User challenge-progress records drive completion state.
6. Server-side queries assemble the nested learning path and calculate progress for the UI.
Another useful story is the AI tutor endpoint: a user submits a sentence, the server calls Gemini with a structured teaching prompt, and the route returns the generated correction/explanation/reply.

Project 2 — Google Maps Lead Scraper and Enrichment API
Backend repository: https://github.com/Kshitij-Vijay-Pawar/scraper
Frontend repository: https://github.com/Kshitij-Vijay-Pawar/scraper-ui
Type: Full-stack lead-generation and web-scraping application
Portfolio priority: Featured project
Overview
This project is a lead-generation system that accepts a business keyword and location, runs Google Maps scraping as an asynchronous background job, stores business records, removes duplicates, enriches records from business websites, and exports lead data.

The backend and UI are separate repositories. Present them as the backend and frontend of the same product only if Kshitij confirms they were developed and deployed together as one application.
Backend: verified implementation
Google Maps scraping
- Uses Playwright Chromium in headless mode to navigate Google Maps.
- Searches using a combination of business keyword and location.
- Detects and attempts to handle a Google consent screen.
- Waits for business-place links and scrolls the results feed to load more results.
- Stops scrolling when the requested limit is reached, the feed ends, or repeated scroll attempts stop changing the feed.
- Opens individual business result pages and extracts available details.
- The scraper code includes extraction for business name, rating, review count, address, phone, website, and geographic coordinates. Additional fields should only be listed if confirmed in the complete extraction and persistence flow.
Asynchronous job processing
- Express 5 API exposes search endpoints.
- Search requests are validated with Zod.
- The API creates a search record in PostgreSQL and queues a BullMQ job.
- The API returns a search ID and job ID without waiting for the scrape to finish.
- A separate BullMQ worker processes the search job.
- The worker updates search status and progress as it moves through scraping and persistence/deduplication steps.
- Redis is used as the BullMQ connection.
- The API includes graceful shutdown handling for the HTTP server, queues, and Redis connection.
Lead deduplication
The deduplication service checks records using a priority strategy:
1. Website.
2. Phone number.
3. Email address.
4. Normalized business name plus address when website, phone, and email are unavailable.
It also uses in-memory sets to detect duplicates within the current batch and batch database queries to compare incoming records against existing records. This is a strong technical detail to highlight because it shows more than simply scraping and inserting rows.
Website enrichment
- Uses Axios to fetch business websites.
- Uses Cheerio to parse HTML.
- Extracts email addresses from mailto: links and page text.
- Discovers and visits a limited number of same-domain contact/about/team/support pages.
- Extracts social profile links for Facebook, Instagram, LinkedIn, and X/Twitter.
- Selects a preferred email using a priority list such as sales, contact, info, support, and admin.
- Preserves the original Google Maps data as the primary source of truth: enrichment is designed to fill missing fields rather than overwrite existing non-null values.
Enrichment jobs
- Enrichment requests are queued separately through BullMQ.
- The API checks that selected leads belong to searches owned by the requesting user.
- The API limits an enrichment job to 500 leads.
- The worker processes leads in batches of five with worker concurrency configured to five.
- It tracks completed and failed leads, updates job progress, skips already-enriched leads unless forced, and checks for cancellation between batches.
- The API exposes enrichment progress and cancellation routes.
Export
- Exports lead records to CSV and Excel (.xlsx).
- Export data includes fields such as name, phone, email, website, address, rating, review count, social links, latitude, and longitude.
- Export routes check search ownership before returning files.
API access and security-related code
The repository includes:
- User authentication middleware.
- API-key authentication middleware and a combined auth-or-API-key middleware.
- API-key routes.
- Audit-log middleware.
- Search ownership checks for user-specific data and exports.
- Zod request validation.
Do not claim a specific security certification or comprehensive security audit.

- Cheerio-based crawling and analysis modules, with individual adapters for the external data sources.
- Asynchronous audit execution using BullMQ and Redis, with a separate worker process.
- Audit status and progress persistence, including current step, percentage, completion state, and error state.
- Anthropic Claude API integration using a structured SEO audit prompt and typed/validated response handling.
- PostgreSQL persistence through Prisma for clients, audits, recommendations, issues, and notification logs.
- Transactional updates for the audit result and its recommendations/issues.
- Executive PDF generation using Puppeteer.
- Admin UI to trigger an audit and inspect progress; client-facing report UI with scores, issues, recommendations, and PDF download.
- Scheduled audit trigger endpoint with bearer-token protection.
- Mock-mode support for external integrations, so the workflow can be exercised without every external API configured.
